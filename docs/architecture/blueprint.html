Polychoron AI — Architecture Drawing Set

Fourteen sheets covering the platform as it actually exists today: the Suite→Feature platform shell and its one live feature, AML Detection. Every box, table and arrow on every sheet is drawn from the checked-in code and migrations, not from the aspirational spec — where a spec describes something not yet built, the sheet says so.

A-101

System Context — C4 Level 1

SCALE NTS · REV A

Five human roles and four outside systems around one platform boundary. The platform never auto-files anything — every arrow crossing the boundary into a regulator or the bank's own core systems is either read-only or a human-triggered write.

A-102

Containers — C4 Level 2

SCALE NTS · REV A

Four deployable processes. app-api and agent-service never call each other directly — the boundary spec makes this structural, not a convention: Temporal is the only cross-service link, so the human-facing half and the agent-facing half of the constitution stay enforced by construction.

A-103

Components — app-api

SCALE NTS · REV A

One controller per screen, all sitting behind the same two guards. SessionGuard resolves the demo session; RolesGuard checks @RequireRoles(...) per route — enforced server-side regardless of what the UI shows, per constitution rule 7.

A-104

Components — agent-service

SCALE NTS · REV A

The part of the diagram that changed most recently: graph.py is a real langgraph.StateGraph, Postgres-checkpointed, with each Temporal activity resuming one node forward — not the plain sequential calls this used to be.

A-201

Deployment Topology — Docker Compose

SCALE NTS · REV A

One host, one docker-compose.yml, ten services. Three are one-shot init jobs gated by service_completed_successfully — nothing races the schema or seed data it needs.

known local gotcha: on Windows/WSL2, both nest start --watch and Vite's file watcher can go stale across a bind mount and silently miss new files — a container restart forces a fresh compile if a route/component seems to be "missing" after an edit.
A-301

ERD — Platform Core

SCALE NTS · REV A

Shared forever, per specs/platform/02-platform-data-models.py — a second feature or suite reads and extends this layer, never forks it.

A-302

ERD — AML Case Lifecycle

SCALE NTS · REV A

Every table one case actually writes through, migrations 003–005. Write ownership is split at the table level per the boundary spec — marked below.

A-303

ERD — Governance & Reporting

SCALE NTS · REV A

All app-api-owned, all added this session. aml_typology_configs replaced the Phase 1 hardcoded catalog the Pattern Matching node used to read from.

A-304

ERD — Regulatory Knowledge Base

SCALE NTS · REV A

Platform-level mechanism, feature-owned content — regulatory_documents.feature_code is the only thing that makes this AML's corpus rather than a shared one.

A-401

End-to-End Case Flow

SCALE NTS · REV A

One alert's full journey. The single redline crossing is the only point in the whole system where a machine recommendation becomes a human decision.

A-501

Sequence — Alert Ingestion & Workflow Kickoff

SCALE NTS · REV A

POST /api/v1/features/aml_detection/alerts/ingest — case row and workflow start happen in the same transaction's shadow; the caller gets the case ID back immediately, the agent chain runs asynchronously after.

A-502

Sequence — Agent Chain Execution

SCALE NTS · REV A

One activity's real path. The same sequence repeats for the other two activities, each time resuming the LangGraph checkpoint one node forward instead of starting over — this is what keeps Temporal's per-node retry isolation intact.

A-503

Sequence — Human Checkpoint → Disposition → Filing

SCALE NTS · REV A

The officer's disposition is the signal that resumes a workflow that's been paused, potentially for days. Only file_str/file_ctr continues on to the filing branch.
